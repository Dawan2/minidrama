# 02 — 全量用户旅程（User Journeys）

> Wave 1 · 计划槽 P2。配套：`docs/02-information-architecture.md`（IA/路由/返回栈/状态框架，下称 IA）、`docs/02-screen-inventory.md`（逐屏状态）。
> 接口引用 `docs/12-api-contracts.md`（下称契约），错误码引用 `docs/12-error-catalog.md`（下称错误目录），平台时序引用 `docs/11-api-and-bridge.md`（下称桥接）。
> 契约缺口以 IA §10 的差距编号（G1–G8）标注，不在本文重复解释。

## 0. 约定

- 每条旅程按 **前置 → 主流程 → 异常分支** 组织。主流程表的"接口"列为契约端点；异常分支表以错误码/条件为键。
- 屏幕/面板以 `02-screen-inventory.md` 的编号引用（SCR-xx / PNL-xx / CMP-xx）。
- 所有旅程共享 IA §8 的全局降级框架（五态、重试、弱网横幅），分支表只写**旅程特有**的处理，通用部分不重复。
- 埋点动作引用领域模型 §8.2 的 `RecEvent` 枚举（IMPRESSION/CLICK/PLAY_START/PLAY_COMPLETE/UNLOCK/FAVORITE）。

旅程总览：

| # | 旅程 | 核心验证点 |
|---|---|---|
| J1 | 冷启动首访 | 启动序列、静默登录、匿名降级 |
| J2 | 浏览→试看→付费墙→充值→解锁→续播 | 黄金路径 + 支付/解锁全部失败分支 |
| J3 | 回访续播 | 进度恢复、追剧列表 |
| J4 | 深链进入 | 解析管线、合成栈、锁定集落地 |
| J5 | 广告解锁 | IAA 探测、isEnded 判定、失败不发奖 |
| J6 | VIP/订阅 | 订阅通道、到期降级 |
| J7 | 整剧解锁 | 报价、价格变更、二次确认 |
| J8 | 收藏与追剧管理 | 幂等收藏、历史移除 |
| J9 | 评论 | 功能开关、审核态可见性、禁言 |
| J10 | 授权拒绝与游客受限 | 显式授权拒绝、匿名触付费 |
| J11 | 支付失败恢复 | 取消/失败/回调延迟/订单关闭/意图恢复 |

| J14 | 封禁与冻结 | 只读模式、资金拦截 |

## J1 冷启动首访

前置：用户从 TikTok 任意入口首次打开小程序（无本地会话）。

主流程：

| 步 | 用户所见 | 系统行为 | 接口 |
|---|---|---|---|
| 1 | 平台加载页（含 ToS/隐私政策，平台渲染） | `TTMinis.init({clientKey})` | — |
| 2 | SCR-01 启动页（品牌 + 进度） | `TTMinis.login()` 取 code → 后端换会话（桥接 §4.1；契约缺 provider=TIKTOK，差距 G1） | `POST /auth/login` |
| 3 | 同上 | 拉取功能开关与配置 | `GET /config` |
| 4 | SCR-02 首页，推荐流渲染，继续观看卡片置顶（新用户无此卡） | 首屏 feed；曝光埋点 IMPRESSION | `GET /recommendations/feed?scene=HOME` |

异常分支：

| 分支 | 条件/错误码 | 处理 |
|---|---|---|
| SDK 初始化失败 | init 异常/超时 | SCR-01 终态错误 + 重试按钮（IA §8.4：不带病进入） |
| 静默登录失败 | `login` 拒绝/超时、`AUTH_PROVIDER_ERROR` | 匿名模式进首页（IA §8.4）；操作点再触发登录（J10） |
| 账号被封禁 | `AUTH_USER_BANNED` | 进入只读模式（J14） |
| /config 失败 | 网络/5xx | 内置保守默认开关进入，后台重拉（IA §8.4） |
| feed 失败 | 网络/5xx | SCR-02 可重试错误态；重试成功前 Tab 仍可切换 |
| feed 为空 | 成功但 0 items | SCR-02 空态（服务端应以热门兜底，空态属于服务端异常的兜底表现） |

## J2 黄金路径：浏览 → 试看 → 付费墙 → 充值 → 解锁 → 续播

前置：已登录（静默），钱包余额不足以解锁目标集。这是收入主链路，所有分支必须闭环。

主流程：

| 步 | 用户所见 | 系统行为 | 接口 |
|---|---|---|---|
| 1 | 首页卡片 → 点击（CLICK 埋点，携 `trackingId`） | 进入剧详情 SCR-04 | `GET /dramas/{id}`（+ `GET /dramas/{id}/episodes` 首页签） |
| 2 | 点「立即观看」 | push 播放器 SCR-05，从第 1 集或 `viewer.lastWatched` 续播 | `POST /episodes/{id}/playback-token` |
| 3 | 免费集连续观看（PLAY_START / PLAY_COMPLETE 埋点；心跳上报进度） | 集尾自动切下一集（路由 replace，IA §6 B4） | `PUT /progress/episodes/{id}` |
| 4 | 滑到第 6 集（`viewerAccess.playable=false, reason=NEED_UNLOCK`，契约 §3.3） | 播放器锁定态（S6）：封面 + PNL-02 解锁面板（价格来自集详情/令牌 403 的 `details`，不额外请求） | — |
| 5 | 点「解锁本集 · 300 看点」→ 余额不足 | 解锁请求返回 402；面板就地转入充值引导，预选覆盖差额的档位（错误目录 §11） | `POST /episodes/{id}/unlock` → `402 WALLET_INSUFFICIENT_BALANCE` |
| 6 | PNL-03 充值面板：档位列表 + 支付通道 | 记录**解锁意图**（episodeId + 幂等键）到本地，供支付后恢复 | `GET /wallet/products` |
| 7 | 选档位 → 拉起支付 | 下单（幂等键）→ `paymentPayload` 交给 `TTMinis.pay`（桥接 §4.2；通道枚举差距 G2） | `POST /wallet/recharge-orders` |
| 8 | 平台支付面板（TikTok 接管）→ 支付成功返回 | 轮询订单至 `CREDITED`（1s/2s/4s… 上限 60s） | `GET /wallet/recharge-orders/{orderId}` |
| 9 | 「充值成功」Toast；面板自动执行挂起的解锁意图 | 原幂等键发起解锁 → 成功后关闭全部面板 | `POST /episodes/{id}/unlock` |
| 10 | 第 6 集自动开播（UNLOCK 埋点） | 换取播放令牌、续播 | `POST /episodes/{id}/playback-token` |

异常分支（解锁环节）：

| 分支 | 条件/错误码 | 处理 |
|---|---|---|
| 重复解锁 | `409 UNLOCK_ALREADY_UNLOCKED` | 视为成功直接播放（错误目录 §11），多端同时解锁的正常竞态 |
| 策略不允许 | `422 UNLOCK_POLICY_NOT_ALLOWED` | 面板刷新为正确通道（如 VIP_ONLY 集只展示 VIP 通道）；出现即说明客户端数据过期，重拉集详情 |
| 幂等键冲突 | `409 COMMON_IDEMPOTENCY_CONFLICT` | 客户端缺陷兜底：换新键重试一次，再失败报可重试错误 |
| 解锁请求超时 | 网络 | **原幂等键**自动重试 1 次（契约 §2.4 保证安全）；仍失败则面板内错误态，用户手动重试 |
| 并发扣费冲突 | `409 WALLET_CONCURRENT_MODIFICATION` | 原幂等键静默重试 1 次（错误目录约定客户端可原键重试），再失败提示稍后再试 |

支付环节失败分支全部收敛到 J11。

## J3 回访续播

前置：老用户再次打开小程序。

主流程：启动序列（J1 步 1–3，命中本地会话则跳过换取，仅校验/刷新令牌）→ 首页「继续观看」卡片（feed `cardType=CONTINUE_WATCHING`，携 `continueEpisode.positionSec`）→ 一击进入播放器并从断点续播（播放令牌响应含 `resumePositionSec`，契约 §4.4，以服务端为准）。

异常分支：

| 分支 | 条件 | 处理 |
|---|---|---|
| 令牌过期 | `AUTH_TOKEN_EXPIRED` | 全局拦截器静默刷新重放（IA §8.2），用户无感 |
| 刷新令牌失效 | `AUTH_REFRESH_TOKEN_INVALID` | 清会话 → 重走静默登录（J1 步 2）；因为是静默登录，用户仍无感——这是本平台优于常规 App 的点，登录态修复不需要用户参与 |
| 续播集已下架 | 打开时 `410` | 走 J13；继续观看卡片同步失效 |
| 多端进度冲突 | 服务端 LWW（契约 §4.7） | 以服务端返回的 `resumePositionSec` 为准；本地缓存仅做弱网兜底展示 |

## J4 深链进入

前置：用户从 TikTok 视频锚点/分享卡点入，携 `episodeId`。管线定义见 IA §7.2，此处走一遍关键分支。

主流程：启动序列 → 解析参数 → `GET /episodes/{episodeId}` → 合成栈 `[#/home, #/play/:episodeId]`（IA §7.3）→ 播放器。

异常分支：

| 分支 | 条件/错误码 | 处理 |
|---|---|---|
| 目标是付费未解锁集 | 令牌 `403 EPISODE_LOCKED` | **合法落地**：播放器锁定态 + 解锁面板直出（投放的核心转化场景，必须一步到位，禁止先弹去首页） |
| 目标仅 VIP | `403 EPISODE_VIP_REQUIRED` | 锁定态 + 解锁面板（VIP 通道） |
| 内容不存在 | `404 CONTENT_NOT_FOUND` | 回首页 + Toast（IA §7.2） |
| 内容下架 | `410 CONTENT_OFFLINE` | SCR-13 兜底页（带推荐位） |
| 参数非法/缺失 | 校验失败 | 等价普通冷启动，进首页，不提示（用户无从修复，提示无意义） |
| 匿名 + 付费集 | 静默登录失败后深链落付费集，令牌 `401 AUTH_REQUIRED` | 锁定态展示 + 点解锁时触发登录重试（J10） |
| 已在运行中收到新深链（热启动） | 平台重入 | 直接在现有栈上 push/replace 落地页，不重走启动序列 |

## J5 广告解锁

前置：`/config` `features.adUnlock=true`，IAA 可用（`canIUse` 探测通过，桥接 §5.1/§4.3），目标集允许广告解锁。契约缺发放端点（差距 G3），本旅程按语义定义，端点以 W1B 回写为准。

主流程：

| 步 | 用户所见 | 系统行为 |
|---|---|---|
| 1 | 解锁面板「看广告免费解锁」通道（余下次数展示，次数上限为服务端风控，领域模型 §12） | 创建激励视频实例（**每次展示新实例**，桥接 §4.3 最佳实践） |
| 2 | TikTok 全屏激励视频（平台接管） | H5 挂起；返回键不处理（IA §6 B7） |
| 3 | 完整看完，回到播放器 | 回调 `isEnded=true` → 调服务端发放解锁（G3 端点）→ 成功后自动开播 |

异常分支：

| 分支 | 条件 | 处理 |
|---|---|---|
| 中途关闭广告 | `isEnded=false` | **不发奖**（桥接 §4.3 硬规则）；Toast「完整观看才能解锁」，面板保持，可重试 |
| 广告拉取失败/无填充 | SDK 错误回调 | 通道置灰 + 文案「广告暂时不可用」；其他解锁通道不受影响 |
| 能力不可用 | `canIUse=false` 或开关关 | 通道不渲染（IA §9），面板布局自适应 |
| 发放接口失败 | 网络/5xx | **广告已看完但没解锁**是最伤体验的分支：客户端持有本次发放凭据自动重试 3 次（退避），仍失败则提示「奖励发放延迟，稍后自动到账」并本地记账，下次启动补偿校验——具体凭据与补偿语义随 G3 端点定义 |
| 次数超限 | 服务端拒绝 | 通道置灰 + 「今日次数已用完」，引导币/VIP 通道 |

## J6 VIP / 订阅

前置：IAP 已开通。平台侧订阅必须走 `TTMinis.createSubscription`（桥接 §4.4）；契约现以 `productType=VIP` 充值档位建模（差距 G4）。旅程按订阅语义设计。

主流程：SCR-11 VIP 页（权益说明 + 档位）或解锁面板 VIP 通道 → 建订阅单（G4 端点）→ `TTMinis.createSubscription` 平台面板 → 成功后轮询订阅状态 → `users/me` 的 `vip.active=true` → 全部 `COIN_OR_VIP`/`VIP_ONLY` 集的 `viewerAccess` 变为可播（服务端计算，客户端只需刷新当前集详情，领域模型 §3.4）。

异常分支：

| 分支 | 条件 | 处理 |
|---|---|---|
| 订阅取消/失败 | 平台回调 cancelled/failed | 同支付失败模式（J11 分支 1/2），VIP 页保持 |
| VIP 生效延迟 | 支付成功但 `vip.active` 未翻转 | 轮询窗口同 J11；超窗提示「开通确认中」，VIP 页与我的页可手动刷新 |
| VIP 到期 | 服务端时间判定（领域模型 §4.1） | 播放到期后首个 VIP 集时令牌返回 `403`，走锁定态——**不做客户端本地到期判断**，一切以 `viewerAccess`/令牌为准 |
| 到期后已看集权限 | 领域模型 §12 开放问题 3 | IA 不预设；两种产品决策下播放器行为一致（以令牌结果驱动），无返工面 |

## J7 整剧解锁

前置：登录态，目标剧存在剩余付费集。

主流程：解锁面板「解锁全剧」入口 → 报价预览 `GET /dramas/{id}/unlock-quote`（原价/折后/剩余集数，契约 §4.5）→ 二次确认（金额醒目，防误触）→ `POST /dramas/{id}/unlock`（幂等键）→ 成功 Toast「已解锁全剧 68 集」→ 续播。

异常分支：

| 分支 | 条件/错误码 | 处理 |
|---|---|---|
| 报价已变化 | `409 UNLOCK_PRICE_CHANGED` | 重拉报价并让用户重新确认（错误目录 §11），`details.currentPayableCoins` 直接渲染新价 |
| 无剩余付费集 | `422 UNLOCK_NOTHING_TO_UNLOCK` | 入口本不应展示（以解锁记录/viewerAccess 判断）；兜底 Toast「已全部解锁」并刷新 |
| 余额不足 | `402` | 同 J2 步 5–9，解锁意图记为"整剧解锁" |
| 请求超时 | 网络 | 原幂等键重试（大额操作绝不允许双扣，幂等键为唯一安全网） |

## J8 收藏与追剧管理

主流程：详情页/播放器收藏按钮（`PUT /dramas/{id}/favorite`，幂等，乐观 UI：先变状态后请求，失败回滚 + Toast）；SCR-08 收藏列表；SCR-07 追剧列表（`GET /users/me/watch-history`，进度联动生成，领域模型 §7.2）；左滑/编辑移除（`DELETE /users/me/watch-history/{dramaId}`）。

异常分支：空态（未收藏/无历史 → 空态组件带"去首页看看"出口）；列表项对应剧已下架（封面蒙层「已下架」，点击进 SCR-13，可从列表移除）；移除请求失败（回滚 + Toast）；匿名访问（触发静默登录重试，J10）。

## J9 评论

前置：`/config` `features.comments=true`（关闭则全部入口不渲染，`403 COMMENT_FEATURE_DISABLED` 仅作兜底，错误目录 §11）。

主流程：播放器评论入口 → PNL-04 评论面板（根评论分页 `sort=HOT`）→ 发表（`POST /episodes/{id}/comments`）→ 返回 `status=PENDING` 时本地插入顶部并标注「审核中」（仅自己可见，领域模型 §9.1）→ 审核通过后对他人可见。点赞/取消为幂等 PUT/DELETE，乐观 UI。

异常分支：

| 分支 | 错误码 | 处理 |
|---|---|---|
| 内容不合规 | `400 COMMENT_CONTENT_INVALID` | 输入框下方就地报错（`details.reason`），保留草稿 |
| 机审直接拒绝 | `422 COMMENT_REJECTED` | Toast「内容未通过审核」，保留草稿供修改 |
| 用户被禁言 | `403 COMMENT_USER_MUTED` | 输入区置灰 + 「禁言至 {mutedUntil}」 |
| 回复层级超限 | `422 COMMENT_REPLY_DEPTH_EXCEEDED` | UI 本不提供三层入口，兜底 Toast |
| 删除他人评论 | `403 COMMENT_NOT_OWNER` | UI 不提供入口，兜底 Toast |
| 评论区为空 | 0 items | 空态「抢首评」，聚焦输入框 |

## J10 授权拒绝与游客受限

两类"权限拒绝"，处理原则见 IA §9（门槛后置、就地恢复）：

**A. TikTok 显式授权拒绝**（可选能力）：触发点仅两处——"我的"页「完善资料」、评论区首次发言前的可选引导。拒绝后：默认昵称/头像继续用，功能零阻塞；本会话不再主动弹授权；入口常驻"我的"页可随时再发起。**验收红线：拒绝授权后走完 J2 全链路必须无任何阻塞。**

**B. 匿名（静默登录失败）触达受限操作**：

| 触点 | 表现 |
|---|---|
| 解锁/充值/收藏/评论/进度云同步 | 操作点触发一次静默登录重试（用户仅见轻加载）；成功则继续原操作（操作意图保留），失败 Toast「网络异常，请稍后重试」 |
| 我的页资产区 | 展示登录引导卡（点击=重试静默登录），不展示假数据 |
| 免费内容消费 | 完全不受限（契约 §2.2 匿名可读），本地进度仅存设备，登录成功后以 LWW 合并上报 |

## J11 支付失败恢复（专项）

支付链路状态机（契约 §4.6 + 领域模型 §5.3）：`PENDING → PAID → CREDITED`，客户端只信轮询结果，**永不以 `TTMinis.pay` 的前端回调作为入账依据**（桥接 §4.2：以 webhook 为准）。

| # | 分支 | 条件 | 处理 |
|---|---|---|---|
| 1 | 用户取消支付 | pay 回调 `cancelled` | 面板回到档位选择态，订单留 `PENDING`（服务端超时自动关单）；不打扰 |
| 2 | 支付失败 | pay 回调 `failed` | Toast「支付未完成」+ 面板保持；重试走**新订单**（原单不复用，避免渠道侧状态纠缠） |
| 3 | 支付成功但回调延迟 | pay 成功回调，轮询 60s 内未见 `CREDITED` | 面板转「到账确认中」态（可关闭）；关闭后钱包页横幅继续提示；后台在钱包页/下次启动继续轮询；到账后 Toast + 恢复解锁意图（若仍在同一剧上下文） |
| 4 | 轮询遇订单已关闭 | `409 PAYMENT_ORDER_CLOSED` | 提示「订单已超时关闭」；若用户实际已扣款，渠道侧退款由服务端对账处理，客服入口兜底（settings 页 C11 邮箱） |
| 5 | 下单失败 | `404 PAYMENT_PRODUCT_NOT_FOUND` | 档位数据过期：重拉 `GET /wallet/products` 刷新面板 |
| 6 | 渠道不可用 | `503 PAYMENT_CHANNEL_UNAVAILABLE` | 通道置灰 + 「支付暂不可用，请稍后再试」 |
| 7 | 下单请求超时 | 网络 | 原幂等键重试（契约 §2.4）；禁止无键重发造成双单 |
| 8 | 支付中用户按返回 | — | 确认对话框拦截（IA §6 B6）；确认离开后同分支 3 的后台轮询兜底 |
| 9 | 充值成功但解锁意图丢失 | 本地意图记录被清（如进程被杀） | 币已入账无资损；用户回到锁定集时正常走解锁，余额已够，一步完成 |

**设计不变式：任何支付分支下，用户的钱与解锁意图至多丢"意图"，绝不丢钱；意图丢失的恢复成本 ≤1 次点击。**

## J12 播放失败与弱网（专项）

播放链路降级矩阵见 IA §8.3，此处定义用户视角的完整旅程分支：

| # | 分支 | 条件 | 用户所见与恢复 |
|---|---|---|---|
| 1 | 起播失败（令牌层） | `403/410/503`（IA §8.3 表） | 分别进入锁定态/终态错误/可重试错误；锁定态直出解锁面板 |
| 2 | 起播失败（CDN 层） | 首帧超时/内核错误 | 静默重签令牌重放一次 → 仍失败显示错误态「加载失败，点击重试」；重试仍失败给「切换清晰度」次级出口 |
| 3 | 播放中卡顿 | 缓冲耗尽 | 转圈 ≤8s → 自动降清晰度一档 + Toast；已是最低档则保持转圈 + 出现重试入口 |
| 4 | 长暂停后恢复 | `playUrl` 剩余有效期 <30s | 恢复前静默重签，无感（IA §8.3） |
| 5 | 断网 | 网络事件 + 请求连续失败 | 弱网横幅（CMP-06）；已缓冲内容播完为止；进度心跳入本地队列 |
| 6 | 网络恢复 | 网络事件 | 横幅消失；补发进度队列与埋点队列；当前集自动重试起播 |
| 7 | 切集遇弱网 | 下一集令牌请求超时 | 停留当前集尾帧 + 加载指示；15s 超时后错误态；**不自动跳过集**（避免用户失去位置感） |
| 8 | 进度丢失兜底 | 心跳全失败且本地队列丢失 | 服务端仍有上一次成功心跳的位置，最坏回退 `progressHeartbeatSec` 秒（`/config` 下发，默认 10s）——量化可接受损失 |

## J13 内容下架

`410 CONTENT_OFFLINE` 在所有触点的表现必须一致（领域模型 §3.1：Wave 1 下架后不可播，回看权为开放问题 1）：

| 触点 | 表现 |
|---|---|
| 深链落地 | SCR-13 兜底页（reason=OFFLINE，带推荐位） |
| 详情页打开 | 同上 |
| 播放中切到下架集 / 续播打开 | 播放器终态错误「本剧已下架」→ 回首页出口 |
| 收藏/追剧列表项 | 蒙层「已下架」，可移除；点击进 SCR-13 |
| 推荐流 | 服务端不应下发；客户端点击后 404/410 则移除该卡并静默刷新 |

若产品后续决定"已解锁用户保留回看"（开放问题 1），仅服务端 `viewerAccess` 计算变化，本旅程各触点无需改动——这是"可看性全由服务端计算"决策（领域模型交接 §2.4）在 IA 侧的红利。

## J14 封禁与冻结

| 场景 | 触发 | 表现 |
|---|---|---|
| 账号封禁 | 任意接口 `403 AUTH_USER_BANNED` | 清本地会话（错误目录 §11）；进入**匿名只读模式**：可浏览与看免费集，所有写操作与资产入口拦截，"我的"页顶部说明条（含 `bannedUntil` 与申诉邮箱）；不弹阻断式全屏（避免灰色地带用户流失投诉） |
| 钱包冻结 | 资金操作 `403 WALLET_FROZEN` | 仅拦资金操作（充值/解锁），观看已解锁内容不受影响；错误文案 + 客服邮箱 |

## 15. 边界场景速查表（验收清单）

按"上架级交互可靠"要求的八大类逐条对照，作为 Wave 2 UI 验收的基线：

| 类别 | 场景 → 落点 |
|---|---|
| 空态 | 推荐流空（J1）/ 分类无结果（SCR-03）/ 收藏、追剧空（J8）/ 流水空（SCR-09）/ 评论空（J9）——全部有行动出口 |
| 错误 | 五态框架（IA §8.1）+ 各旅程分支表；错误码到 UI 行为的映射以错误目录 §11 为底表 |
| 权限拒绝 | 显式授权拒绝零阻塞（J10-A）/ 匿名操作点重试（J10-B）/ 封禁只读（J14）/ IAA·IAP 未开通隐藏通道（IA §9） |
| 支付失败 | J11 全部 9 分支；不变式：不丢钱、意图恢复 ≤1 次点击 |
| 播放失败 | J12 全部 8 分支 + IA §8.3 降级矩阵 |
| 弱网 | 超时/重试/退避（IA §8.2）/ 心跳与埋点队列（J12-5/6）/ 面板内就地错误（IA §8.1） |
| 返回栈 | 规则 B1–B8（IA §6）；重点：面板优先关闭、切集 replace、支付拦截、深链合成栈 |
| 深链 | 管线与回退矩阵（IA §7、J4）；红线：永不白屏、永不死路、锁定集直出付费墙 |
