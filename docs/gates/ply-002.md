## What this repository now owns (not a host measurement)

A fail-closed **contract probe** in `app/src/player/ply-002-probe.ts` and
`app/src/player/ply-002-probe.test.ts`. It is the subset a cloud agent / jsdom / Node process can
honestly enforce without those WebViews:

| Property | What is pinned | What a mutation does |
| --- | --- | --- |
| **getPlayer ctor** | `createPlayerFacade` calls `bridge.getPlayerCtor()` once and constructs that return | Building `MockVePlayer` (or `window.TTMinis.getPlayer`) in the facade fails the suite |
| **replace-element** | `refuseVideoReplace` returns `null`; TikTokBridge installs that callback on the constructor `getPlayer()` returns | Returning the original `<video>` or skipping the installer fails the suite |
| **no MSE URL leak** | VePlayer config + `setPreloadList` items have no URL-shaped key or value. Player/platform production source does not construct `MediaSource` / `ManagedMediaSource`, import hls.js, or embed `.m3u8` / `playUrl` | A `playUrl` on the constructor, a `vid` that is an `https://…m3u8`, or `new MediaSource()` in `src/player` fails the suite |

`enableMp4MSE: true` remains the VePlayer **construction flag** (`docs/plan/media-plane-decision.md`
§5.3 exception). It is not a locator. The probe allow-lists that exact key because a naïve
`mp4` regex would treat the flag as a leak.

`measurePly002EquivalentHost()` always returns `status: 'unmeasured'`. It does not read
`MediaSource` in this process. jsdom's presence or absence of that constructor is not Android
WebView and is not WKWebView.

The session body is already fail-closed on URLs (`app/src/data/playback-api.ts`
`narrowPlaybackDescriptor`, `server/src/modules/playback/playback-contract.test.ts`). This probe
is the **player-side** half: what reaches `new ctor({…})`.
