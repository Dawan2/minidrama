## 2. What changed

`pnpm run check:commits` reads `git log origin/main..HEAD`. A missing git binary, a missing
`origin/main`, or a malformed log is red. An empty range is 0 new commits (history on `main`
is not rewritten), not a skip. A one-parent prose subject is red. A Conventional header
without a requirement/defect id (`D-20`, `G1.9`, `C5-01`, …) is red. Two-parent merge
commits are how a work branch absorbs `main`; they are not a hit.

G1.9 is folded into `pnpm verify` (git is already required) and is a named L1 step. There is
no `continue-on-error`.

| File | Change |
| --- | --- |
| `packages/quality/src/commits.ts` | Parse + policy |
| `packages/quality/src/cli/check-commits.ts` | Process boundary |
| `.github/workflows/ci.yml` | Step `G1.9 commit convention` after typecheck |
| `package.json` | `check:commits` in `verify`, before `check:skips` |
| `docs/14-quality-gates.md` §2.1 | Dated note: G1.9 is the job |

## 3. Reverse verification

Against a fixture whose new commit is `Add the lint job`:

```
commit-check failed (1): new commits that are not Conventional Commits with a requirement/defect id are G1.9 red
  prose <hash> Add the lint job
```

Exit 1. Against `feat: add a widget` (Conventional, no tracker):

```
commit-check failed (1): new commits that are not Conventional Commits with a requirement/defect id are G1.9 red
  missing-id <hash> feat: add a widget
```

Exit 1. Against a missing `origin/main`:

```
commit-check base is required: origin/main is absent — G1.9 does not rewrite history and will not invent a range
```

Exit 1. Against `main` itself (empty range):

```
commit-check passed (0 new commits vs main): G1.9 does not rewrite history
```

Exit 0. An unknown argument exits 2 rather than being ignored. A comment that says we use
Conventional Commits is not this gate.
