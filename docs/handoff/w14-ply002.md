## 3. Mutations that bite

Run against this branch, then reverted.

### 3.1 Host status flipped to `available`

`measurePly002EquivalentHost` returning `{ status: 'available', … }` fails:

```
FAIL  PLY-002 host measurement stays fail-closed > does not invent an equivalent-WebView MSE/EME result in this process
AssertionError: expected 'available' to be 'unmeasured'
```

Installing a jsdom `MediaSource` spy and constructing it inside the measurement fails the
"does not construct MediaSource" test.

### 3.2 Facade skips `getPlayerCtor`

```
FAIL  getPlayer ctor > constructs the player only through bridge.getPlayerCtor
expected "spy" to be called 1 times, but got 0 times
```

The source assertion that `player-facade.ts` contains `bridge.getPlayerCtor()` fails the same
way if the call is renamed to a direct SDK global (the identifier is assembled in the test so
the source-tree rule still accepts this file).

### 3.3 A `playUrl` on the constructor config

`leakingMediaHandleKeys({ playUrl: 'https://cdn.example/a.m3u8' })` is asserted to equal
`['playUrl']`. A facade that forwarded a locator would fail "hands VePlayer identifiers and
the MSE flag, never a locator". `enableMp4MSE` still matches a naïve `mp4` regex and is
allow-listed on purpose.

### 3.4 `refuseVideoReplace` returns the original element

The replace-element tests expect `null`. Returning the stand-in `<video>` fails them, as it
already does in `video-replace.test.ts`. This suite pins the constructor-shaped installer
without naming the SDK global (product files outside `src/platform/` must not).
