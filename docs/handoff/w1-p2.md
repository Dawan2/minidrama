## 2. 关键设计决策（及理由）

1. **三层导航（Tab 根/push 页/覆盖层面板），面板不占路由**：短剧的付费转化都发生在播放器内，选集/解锁/充值/评论全部做成覆盖层，转化路径零跳页；面板以 history state 参与返回栈（返回先关面板），兼容 Android 手势返回。
2. **播放器集间切换一律 replace**：80 集剧不撑爆返回栈，从播放器返回一步回到入口页。
3. **深链冷启动合成栈 `[home, 落地页]`**：投放回流用户按返回不退出小程序而是落到首页，为留存关键路径；深链失败矩阵保证"永不白屏、永不死路、锁定集直出付费墙"。
4. **锁定态是播放器的一等状态而非错误**：`403 EPISODE_LOCKED` 的 `details`（价格/策略）直接渲染解锁面板，不再发额外请求——深链到付费集即最短转化路径。
5. **门槛后置的权限模型**：静默登录失败降级为匿名浏览，操作点才重试登录且保留操作意图；显式授权被拒绝零阻塞（验收红线）。本产品没有登录页。
6. **支付以轮询订单终态为唯一入账依据**（前端 pay 回调仅作 UX 提示），解锁意图本地持久化、到账后自动恢复；不变式："任何分支不丢钱，意图恢复 ≤1 次点击"。
7. **播放令牌短时效的全生命周期管理**：`expiresAt` 预判静默重签、临近集尾预取下一集令牌、CDN 失败先重签再报错——把防盗链设计（契约 §4.4）的 UX 代价压到无感。
8. **五态（加载/内容/空/可重试错/终态错）作为逐屏验收基线**，覆盖层内错误就地处理不污染底层页面；弱网下进度与埋点走本地队列补发，量化最坏进度损失（≤1 个心跳间隔）。

## 3. 交叉核对发现的上游差距（需 W1A / W1B 回写）

详表见 `02-information-architecture.md` §10（G1–G8），按阻塞程度排序：

| 优先级 | 差距 | 归属 |
|---|---|---|
| 高（阻塞黄金路径） | G1 登录 provider 缺 `TIKTOK`；G2 支付渠道缺 `TIKTOK_BEANS` 且 `paymentPayload` 需约定 `tradeOrderId` | W1B 契约 |
| 高（阻塞必接能力对应旅程） | G4 VIP/订阅通道错位（契约按充值单建模，平台要求订阅端点 + `createSubscription`） | W1B 契约（与 W1A 开放问题 Q3 联动） |
| 中 | G3 广告解锁无发放端点（`features.adUnlock`/`method=AD` 已留位）；G8 币价与发行区域货币口径（契约按人民币分，发行区域为 TikTok Minis 区域集） | W1B + 商务 |
| 低 | G5 搜索端点缺失（入口已预留默认隐藏）；G6 平台启动参数 API 待实测；G7 分享 API 待确认 | G5 产品决策→W1B；G6/G7 → W1A 开放问题清单 |
