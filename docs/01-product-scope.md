# 01. 产品范围（Product Scope）— TikTok Minis 短剧小程序

> 工作槽：W1 P1 · 日期：2026-08-27
> 本文是产品功能边界的唯一权威文档。平台入驻要求见 `docs/01-tiktok-minis-requirements.md`；官方逐项对照表见 `docs/11-official-onboarding-checklist.md`；接口与领域语义见 `docs/12-*`。
> 质量目标（恒定）：功能完备、可真实入驻 TikTok Minis、交互可靠、上架级无 bug。

## 1. 产品定位

在 TikTok App 内（TikTok Minis / Mini Drama H5 路径）运行的竖屏短剧小程序：用户免安装进入，刷剧、按集付费或看广告解锁、跨设备续看。变现以「Beans 单点解锁 + 广告解锁」为主线，订阅按平台必接要求完成集成、作为二期运营重点（沿用 W1A 决策，见 `docs/11-api-and-bridge.md` §4.4）。

**北极星验收**：以真实企业主体走完官方 6 阶段入驻流程并全量上线，线上版本通过本文档 §6 质量门。

## 3. 用户与核心场景

| # | 场景 | 旅程 |
| --- | --- | --- |
| U1 | 刷到即看 | 从 TikTok 内入口（投流锚点/Mini Center）进入 → 静默登录无感完成 → 落到剧详情或直接起播 |
| U2 | 追剧付费 | 免费看前 N 集 → 触达付费墙 → 充值 Beans 换币解锁单集/批量解锁，或看激励视频广告解锁 → 继续观看 |
| U3 | 跨端续看 | 手机 A 看到第 12 集 8 分 20 秒 → 手机 B 打开「继续观看」恢复到同一位置 |
| U4 | 找剧 | 首页 Feed 浏览 / 分类筛选 / 搜索 → 进详情 → 收藏或直接播放 |
| U5 | 出问题能自助 | 支付掉单/播放失败 → 界面给出明确错误与恢复动作 → 不行则通过举报/申诉邮箱触达（72h SLA，见 `01-tiktok-minis-requirements.md` §6） |

## 4. 功能范围明细

每个模块给出：范围内清单、明确边界、验收要点。接口契约一律以 `docs/12-api-contracts.md` 为准，此处不重复字段。

### 4.1 登录与账户

- **范围内**：静默登录（`TTMinis.login` → 后端换 `open_id`，用户无感，必接）；显式授权（昵称/头像，仅在个人中心展示需要时触发，可拒绝且拒绝后功能不降级）；会话管理与 token 刷新；账户注销申请入口（合规要求）。
- **边界**：无独立注册/密码体系；无手机号/邮箱绑定；身份唯一主键为 `open_id`（W1B）。
- **验收要点**：冷启动到登录完成无用户可感知打断；登录失败有重试入口（错误码见 `12-error-catalog` AUTH 域）；`client_secret` 永不出现在前端产物（代码扫描红线）。

### 4.2 目录与发现

- **范围内**：首页 Feed（规则混排 + 曝光回传）；剧详情页（封面、简介、分级标识、集列表、解锁状态总览）；分集列表（跨季全局集序，W1B 决策 10）；分类/标签筛选；搜索（剧名/标签）；收藏（追剧列表）。
- **边界**：不做个性化算法排序（首发）；不做话题/榜单运营位（二期）。
- **验收要点**：所有列表支持游标分页与空态/加载态/错误态三态 UI；集列表明确标识每集 `viewerAccess`（免费/已解锁/需解锁/不可用）。

### 4.3 播放器

- **范围内**：竖屏全屏播放；单击暂停/继续、双击点赞（联动收藏可后置）；进度条拖拽与预览时间提示；倍速（0.75/1/1.25/1.5/2）；上下滑切换上/下一集；自动连播（本集完→下一集，遇付费墙停在解锁页）；付费墙拦截页（锁定集试图播放时展示解锁选项：币解锁/广告解锁/充值）；播放令牌过期自动静默换发重试；导航栏与安全区适配（`setNavigationBarColor`、菜单按钮避让，必接）。
- **边界**：清晰度切换视片源转码能力在 W2 定案（多档转码在范围内为「应做」，单档兜底可上线）；不做画中画/后台播放（WebView 能力受限）。
- **验收要点**：起播时间达 §5 预算；拖拽/切集/倍速在低端机不掉帧卡死；锁定集在任何入口（连播、深链、切集）都被服务端拦截而非仅 UI 隐藏。

### 4.4 续看与观看历史

- **范围内**：播放进度心跳上报（周期 + 关键事件触发）；跨设备续看（LWW 按 `clientUpdatedAt`，W1B 决策 6）；首页「继续观看」卡片直达上次位置；观看历史页（由进度联动更新，允许最终一致）。
- **边界**：多端同时播放不做互踢（登记为开放问题，W1B §4.5）。
- **验收要点**：杀进程/断网后重进恢复位置误差 ≤ 5 秒；过旧上报被静默忽略且不报错。

### 4.5 支付、钱包与解锁

- **范围内**：
  - 钱包：应用内虚拟币双账户（充值币 + 赠币，先赠后充，W1B 决策 2）；余额与明细页。
  - 充值：Beans 档位映射自有币档位（档位以官方定价页实时为准，Q2）；建单→`TTMinis.pay`→webhook 发货闭环；掉单补偿（用户可手动「恢复购买」触发对账）。
  - 解锁：单集解锁、批量/整剧解锁（含折扣定价位）；剧级「前 N 集免费」优先于集级策略；解锁凭证永久有效（剧下架回看权为开放问题）。
  - 广告解锁：激励视频完整观看（`isEnded === true`）解锁单集或发放金币；每日次数上限（风控值 W3 定）；插屏广告位按平台必接完成集成，展示策略保守（不打断播放中场景）。
  - 订阅：按必接完成「创建订阅 + 订阅管理页（查看/到期）」，首发不做订阅专属内容池（二期运营）。
- **边界**：无退款自助通道（走举报/申诉邮箱人工处理）；不做币赠送/转账。
- **验收要点**：同一订单重复回调不重复发货（幂等以渠道订单号）；支付成功但发货失败有补偿任务兜底；所有资金操作可从明细页对账；未完整观看广告不发奖。

### 4.6 内容分级与内容池管理

平台无公开的分级 API，分级是**我方内容准入制度**，用于保证内容 100% 落在官方《Content Requirements》（S14，10 大类禁区）允许范围内：

- **范围内**：
  - 内容准入自审流程：每部剧上架前对照 S14 十大类逐条自查（暴力血腥、身体暴露与性化行为、青少年安全、仇恨言论、管制商品等），短剧常见高危题材的红线映射表见 `01-tiktok-minis-requirements.md` §5。
  - 内部分级标签（如 G 全龄 / T 青少年慎看题材），落库为剧元数据；分级标识在详情页展示。
  - 题材涉及真实事件改编时展示「纯属虚构」免责声明（S14 Integrity 条款的明确要求）。
  - 版权链路管理：每部剧登记授权文件，支撑「版权内容自查表」签署（checklist C9）。
- **边界**：不做按用户年龄的内容过滤（TikTok 侧无年龄 API 暴露给 Minis；以内容准入保证全部内容平台合规）。
- **验收要点**：内容库中不存在未过自审流程的剧；自审记录可回溯到人与日期。

### 4.7 合规与隐私

- **范围内**：ToS 与隐私政策页面（加载页对用户展示，需正式 URL，checklist C4/C5）；数据最小化（默认仅 `open_id` + 业务数据，昵称头像仅显式授权后存储）；数据删除（注销）流程；举报/申诉联络邮箱（2FA，用户申诉时邮箱会被共享给用户，S15）；用户举报 72 小时内处理的运营值守（S15，进 W48 运营手册）。
- **边界**：GDPR/各区域隐私细则逐区评审在 W3 法务任务中定（首发区域选择影响范围）。
- **验收要点**：隐私政策声明的数据项与实际采集完全一致（含埋点字段）；注销后个人数据按承诺清除。

### 4.8 埋点与数据

- **范围内**：客户端埋点 SDK（批量上报 `/events/batch`，W1B）；核心漏斗事件：进入 → 登录成功 → 首次播放 → 触达付费墙 → 发起支付/广告 → 解锁成功 → 次日回访；播放质量事件（起播时长、卡顿、播放失败）；曝光回传（Feed `trackingId`）；事件字典 W3 定稿为唯一权威。
- **边界**：不接第三方分析 SDK（域名受可信域名 ≤20 限制，且有代码扫描风险）——自建上报到自有后端。
- **验收要点**：事件字典中每个事件可在后端查证；弱网下事件本地缓存补报不丢失（容量上限与丢弃策略 W3 定）。

### 4.9 错误态（一等需求）

- **范围内**：以 `docs/12-error-catalog.md` 为唯一错误码权威，前端按 code 分支处理；每个错误码必须映射到「用户文案 + 恢复动作」二元组（如 `WALLET_INSUFFICIENT_BALANCE` → 文案 + 跳充值）；全局兜底错误页（未知错误/崩溃恢复）；平台能力不可用降级（`canIUse` 探测失败 → 结构化错误 → 引导升级 TikTok App，对应最低 SDK 版本 C7）。
- **验收要点**：错误码 × UI 映射表 100% 覆盖（W31 出场标准）；不出现裸异常 toast、英文报错串或空白屏。

### 4.10 弱网与可靠性（一等需求）

- **范围内**：网络分层策略——关键读（目录/详情）超时 + 指数退避重试 + 骨架屏；写操作（支付/解锁）不自动重试、以幂等键支持用户手动重试；播放弱网降级（缓冲提示、必要时降清晰度/提示切换网络）；断网提示与自动恢复监听；进度与埋点本地缓存断网补报。
- **测试矩阵（W32/W39 验收基线）**：弱网档位（2G/3G/高丢包/高延迟）× 关键旅程（登录、起播、拖拽、切集、支付、解锁、续看恢复）。
- **验收要点**：任何弱网组合下不出现卡死、重复扣费、状态不一致；恢复网络后无需重启即可继续。

## 6. 「上架级无 bug」质量门定义（W40 终审依据）

1. **零 P0/P1**：P0 = 崩溃、资金错误（多扣/少发）、无法登录/播放；P1 = 核心旅程（U1–U5）任一步骤失败或数据不一致。P2 允许带已知问题上线但须有处置结论。
2. **错误态全覆盖**：§4.9 映射表 100%，抽查 20 个错误注入场景全部呈现设计内 UI。
3. **弱网矩阵全过**：§4.10 矩阵无卡死/重复扣费/状态错乱。
4. **资金零容差**：对账脚本连续 7 天（或等效压测量）零差异；重复回调/乱序回调用例全过。
5. **平台必接自检全过**：checklist §5 D4–D9 与 §6.2 E5–E9 全部 `[x]`。
6. **双端真机全过**：Android（测试客户端）与 iOS（预览）核心旅程各 2 轮回归通过。
7. **英文走查通过**：全 UI 英文无缺漏、无乱码、无截断。

## 7. 发布切片

官方规定**首发必须全量发布**（Push to production，checklist E13），不存在「小流量试水」的首发选项，因此 MVP 即完整首发集 = §2.1 全部 + §4 全部「范围内」项。灰度能力自第二个版本起可用（W49 演练）。范围压缩只能压 §4 各模块「边界」中标注可后置的项（如双击点赞联动、清晰度多档），不可压必接能力与质量门。
