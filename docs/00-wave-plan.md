# 00. 50 波交付计划骨架（Wave Plan）

> 工作槽：W1 P1（产品范围与规划）· 日期：2026-08-27
> 定位：全项目唯一的波次计划总纲。各波开工时按本骨架细化为当波任务单，完成后回写状态。
> 产品目标：功能完备、可真实入驻 TikTok Minis、交互可靠、上架级无 bug 的短剧小程序。产品范围见 `docs/01-product-scope.md`。

## 1. 工作方式约定

- **波（Wave）**：一轮并行工作。每波含若干工作槽（Work Slot），槽间尽量无共享文件冲突；每槽独立分支 `cursor/w<波次>-<槽名>-1d0f`，只 push 不开 PR，由集成者统一合并。
- **交接**：每槽结束必须产出 `docs/handoff/w<波次>-<槽名>.md`，列明产出、关键决策、阻塞、给后续槽的接口。
- **禁止事项（全项目恒定）**：不删除/跳过测试，不降低 CI 标准，不伪造官方来源（用户 PDF 缺失期间只引用官方网页，来源编号沿用 `docs/11-official-onboarding-checklist.md` §0.2 的 S1–S13 及本波新增 S14/S15，见 `docs/01-tiktok-minis-requirements.md` §1）。
- **完成定义（DoD）**：代码波 = 通过 CI（lint + test + build）+ 交接文档；文档波 = 内容自洽、交叉引用正确 + 交接文档。
- **状态记法**：`[ ]` 未开始 / `[~]` 进行中 / `[x]` 完成 / `[!]` 阻塞。

## 4. 计划维护规则

1. 波次主题稳定、槽拆分灵活：每波开工由当波集成者把「关键产出」拆成并行槽任务单。
2. 阻塞不空转：某波被商务闸门阻塞时，顺位提前后续无闸门波（如 W28、W31–W33 可提前）。
3. 状态回写：每波结束由集成者回写本文状态列与商务里程碑表。
4. 变更走增补：调整波次内容时在本文末尾追加「变更记录」小节，不得静默改写历史计划。
