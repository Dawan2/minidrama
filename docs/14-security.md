# 14. 安全、隐私与内容安全规范(Security)

> **状态**:Wave 1 规范定稿(W1D)
> **适用范围**:minidrama 客户端(App / H5 / 小程序)、后端服务、管理后台、数据管道
> **配套文档**:[14-quality-gates.md](./14-quality-gates.md)(门禁执行)、[14-test-plan.md](./14-test-plan.md)(安全测试用例落点)
>
> **执行原则**:本文档的每一条"必须(MUST)/禁止(MUST NOT)"都要映射为可验证的测试或扫描规则,进入 CI 门禁;**CI 失败即失败,不允许为通过检查而放宽规则**(见质量门禁铁律 R1/R4)。

---

## 1. 威胁模型概述

短剧平台的核心资产与主要威胁:

| 资产 | 主要威胁 | 对应章节 |
|------|----------|----------|
| 用户账号与会话 | 撞库、token 泄露/重放、会话劫持 | §3 |
| 支付与虚拟权益(金币、会员、已解锁剧集) | 伪造支付回调、重复发货、越权解锁、客户端篡改价格 | §4 |
| 视频内容(版权资产) | 盗链、批量下载、录屏分发 | §5 |
| 用户个人信息 | 过度收集、泄露、SDK 违规采集 | §6 |
| UGC(评论、弹幕、头像、昵称) | XSS 注入、违法违规内容、垃圾信息 | §2、§7 |
| 平台可用性 | 刷接口、爬虫、DDoS | §5.3 |

信任边界:**客户端(App/H5/小程序)完全不可信**。一切鉴权、计费、解锁、内容审核决策必须在服务端完成;客户端校验仅用于体验优化。

## 2. XSS 与注入防护

短剧产品的 XSS 高危面:评论、弹幕、昵称、剧集简介(运营录入)、搜索词回显、H5 活动页、WebView 混合页面、深链(deeplink)参数。

### 2.1 强制规则

- **输出编码优先**:所有动态内容按输出上下文编码(HTML 实体 / 属性 / JS 字符串 / URL)。使用框架默认的自动转义(React JSX、Vue 模板),**禁止**使用 `dangerouslySetInnerHTML` / `v-html` 渲染任何含用户输入的内容;确需富文本(运营 CMS 简介)时,必须经过服务端白名单净化(DOMPurify 等价方案,白名单标签集中配置),且净化在**服务端**完成后落库。
- **输入校验为辅**:昵称、评论、弹幕在写入时做长度、字符集、格式校验,但不以"过滤"替代输出编码(过滤可被绕过)。
- **CSP**:H5 与内嵌 WebView 页面必须下发 Content-Security-Policy:`default-src 'self'`;`script-src` 禁止 `unsafe-inline` 与 `unsafe-eval`,使用 nonce/hash;`frame-ancestors` 收敛到自有域。CSP 违规上报(report-uri)接入监控。
- **DOM XSS**:禁止将 `location`、deeplink、URL 参数直接写入 `innerHTML`/`document.write`/动态 `<script>`;deeplink 与 WebView 可加载 URL 必须走**域名白名单**校验(服务端下发白名单),防止任意 URL 加载与 JS bridge 被恶意页面调用。
- **JS Bridge 安全**:WebView 暴露给页面的原生桥接口最小化;每个 bridge 方法校验调用方页面域名在白名单内;涉及 token、支付的 bridge 接口禁止暴露给第三方页面。
- **其他注入**:
  - SQL:一律参数化查询/ORM 绑定,禁止字符串拼接 SQL;CI SAST 规则拦截。
  - 命令注入:服务端禁止将外部输入拼入 shell;转码等任务参数白名单化。
  - SSRF:服务端凡按 URL 抓取资源(如头像导入、封面抓取)必须走出站代理 + 域名白名单 + 禁内网地址段。

### 2.2 验证手段(进 CI)

- SAST 规则集启用 XSS/注入类规则(Semgrep/CodeQL),high 级告警阻断合并(门禁 G2.4);
- 单元测试覆盖净化函数的绕过样本集(polyglot payload 回归集,持续补充);
- E2E 安全冒烟:向评论/弹幕/昵称提交标准 XSS payload,断言渲染后不执行(见 [14-test-plan.md §7.3](./14-test-plan.md));
- 发布级 DAST 扫描(门禁 G3.4)。

## 3. 认证与 Token 安全

### 3.1 Token 模型

- 采用 **短效 access token + 长效 refresh token** 双 token:
  - access token:有效期 ≤ 30 分钟,无状态(JWT)或引用型皆可,由架构槽定;若用 JWT,必须校验 `alg` 白名单(禁 `none`)、`iss`/`aud`/`exp`,签名密钥走 KMS 管理并支持轮换(kid)。
  - refresh token:有效期 ≤ 30 天,**一次性轮换**(rotation):每次刷新颁发新 refresh token 并作废旧值;检测到已作废 token 被重放 → 判定泄露,吊销该用户全部会话并要求重新登录。
- 服务端维护会话/设备维度的吊销能力:改密、异地风控、用户"退出所有设备"必须实时生效(access token 短效 + 吊销名单兜底)。

### 3.2 存储规则(客户端不可信,但要提高窃取成本)

| 端 | 规则 |
|----|------|
| iOS | token 存 Keychain(`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`);禁止 NSUserDefaults / 明文文件 |
| Android | token 存 Keystore 加密的存储(EncryptedSharedPreferences 等价);禁止明文 SharedPreferences / 外部存储;`allowBackup=false` |
| H5 | **禁止将长期 token 放 localStorage/sessionStorage**;会话凭证使用 `HttpOnly; Secure; SameSite=Lax`(跨站场景 `None`+CSRF 防护)Cookie;必要的内存态 access token 不落盘 |
| 小程序 | token 存平台安全存储,不写入分享参数、不打印日志 |

- **禁止 token 出现在**:URL 查询串、日志(客户端与服务端日志脱敏规则强制)、崩溃上报、埋点、分享链接、WebView 通过 URL 传递(必须传递时走一次性短效授权码交换)。

### 3.3 传输与登录安全

- 全链路 HTTPS(TLS ≥ 1.2),App 对核心域名启用**证书固定(certificate pinning)**并预置备用证书;HSTS 全域开启。
- 登录接口:限流 + 图形/行为验证码升级策略 + 撞库检测(同 IP/设备失败次数);短信验证码限频、5 分钟有效、错误 5 次作废。
- 第三方登录(微信/Apple 等):服务端用 code 换取并校验身份,禁止信任客户端直传的 openid/用户资料。
- CSRF:所有 Cookie 会话下的状态变更接口校验 CSRF token 或 `SameSite` + 自定义头双重防护;小程序/App 的纯 Bearer 头方案天然免疫,但禁止同接口混挂 Cookie 鉴权。
- 越权(IDOR):所有资源访问必须在服务端按"当前会话用户"做归属校验(订单、观看记录、收藏列表按 user_id 过滤);资源 ID 使用不可枚举形态(随机 ID),但**不可枚举不能替代鉴权**。越权用例进入契约/集成测试必测项。

## 4. 支付与权益校验(最高风险域)

原则:**金额、商品、权益的唯一真相在服务端;客户端只负责展示与拉起收银台。**

### 4.1 服务端校验规则

- **价格与商品**:下单接口只接受 `product_id`,单价、折扣、应付金额一律由服务端计算;客户端传来的金额字段只用于对账校验,不一致直接拒单并告警。
- **IAP(App Store / Google Play)**:
  - 收据/purchaseToken 必须由**服务端**调用苹果 App Store Server API / Google Play Developer API 验证,禁止客户端本地验证结果直接发货;
  - 校验字段:bundle_id/package_name、product_id 与订单一致、purchase 状态、环境(生产收据拒收沙箱,反之亦然);
  - 处理 App Store Server Notifications / Play RTDN,支持退款回收权益;
  - transaction_id / orderId **全局唯一去重**,防同一凭证重复发货。
- **微信支付 / 支付宝**:
  - 回调必须**验签**(平台证书/公钥,自动更新机制),验签失败直接丢弃并告警;
  - 校验回调中的商户号、订单号、**金额与币种与本地订单完全一致**;
  - 回调处理**幂等**:以订单号加锁/状态机保证同一通知多次送达只发一次货;
  - 主动查单兜底:未收到回调的订单定时向平台查单对账;
  - 每日对账:平台账单与本地订单全量核对,差异生成工单,禁止静默抹平。
- **订单状态机**:`created → paying → paid → delivered`(以及 `closed/refunded` 分支);状态迁移单向、带条件;发货(加金币/解锁/开通会员)必须且只能由 `paid → delivered` 迁移触发,事务内落库。
- **权益校验**:播放付费剧集前,服务端校验用户权益(已解锁/会员有效)后才签发视频播放凭证(见 §5.1);**禁止**客户端仅凭本地状态解锁播放。
- **自动续费**:签约/解约状态以平台侧为准,服务端定时同步;到期扣款失败的降级策略明确并测试。
- **防薅羊毛**:新客优惠、签到奖励等营销发放接口全部限流 + 设备指纹 + 风控规则;金币等虚拟资产的每一笔增减记流水(append-only),支持审计回放。

### 4.2 验证手段(进 CI 与测试计划)

- 支付模块单元测试覆盖:验签失败、金额不一致、重复回调、乱序回调、沙箱/生产环境串号、退款回收 —— 全部为核心模块必测项(覆盖率 ≥ 90%,见门禁 §3.1);
- 集成测试用平台沙箱/本地模拟网关跑全状态机;
- E2E 关键路径含沙箱支付全流程(见 [14-test-plan.md §5](./14-test-plan.md));
- 每次发布前人工核对生产支付配置(门禁 §5.2)。

## 5. 内容防盗链与平台可用性

### 5.1 视频防盗链

- 视频地址一律为**短效签名 URL**(CDN URL 鉴权,有效期 ≤ 播放会话所需,建议 10 分钟内)+ 绑定用户/设备维度参数;
- 播放凭证签发接口做权益校验(§4.1)+ 限流(单用户并发播放数、单位时间取址次数);
- 付费内容启用 DRM 或至少 HLS AES 加密(密钥接口同样鉴权),裸 mp4 直链禁止用于付费内容;
- 监控:同一凭证异常多 IP 使用、取址量突增 → 风控封禁。

### 5.2 管理后台

- 管理后台独立域名 + 强制 SSO/双因素;操作审计日志不可篡改;
- 运营录入内容(简介、活动页)同样过净化与审核流程(§2、§7),内部人员不豁免。

### 5.3 限流与反爬

- 全部开放接口默认限流(网关层),登录、验证码、下单、取播放地址为重点;
- 剧集列表/详情接口做翻页深度与频率限制,防全量爬取;
- 客户端接口签名(请求签名 + 时间戳防重放窗口 ≤ 5 分钟),签名密钥问题见 §8 移动端加固。

## 6. 隐私保护(个人信息合规)

> 合规基线:中国《个人信息保护法》(PIPL)、《网络数据安全管理条例》、工信部 App 侵害用户权益专项整治要求;若出海再叠加 GDPR/CCPA(本 Wave 暂按国内基线,出海由后续 Wave 扩展)。

### 6.1 数据最小化与清单化

- 维护《个人信息收集清单》(字段、目的、存储位置、保留期、是否委托第三方),入库版本管理;**代码中新增采集字段必须同步更新清单**,发布门禁 G3.5 核对;
- 不收集与业务无关的信息;设备标识优先使用平台合规方案(iOS 用 IDFV/ATT 授权后的 IDFA;安卓优先 OAID),**禁止**私自读取 IMEI/MAC 等;
- 敏感字段(手机号、支付信息)落库加密或脱敏,展示层掩码;日志与埋点全链路脱敏(自动化脱敏规则 + 日志抽检)。

### 6.2 用户权利与告知

- 首次启动:隐私政策弹窗,**同意前不初始化任何采集类 SDK、不发送任何含设备标识的请求**(此项为发布级自动化检测:抓包断言同意前零上报);
- 提供:注销账号(15 个工作日内完成数据删除/匿名化)、导出个人信息副本、撤回同意、个性化推荐关闭开关;
- 未成年人:青少年模式(时长限制、消费限制、内容池隔离、宵禁时段),疑似未成年消费的退款通道与流程。

### 6.3 第三方 SDK 治理

- SDK 准入评审:采集行为声明、隐私政策、版本安全记录;维护 SDK 清单与版本;
- SDK 初始化统一收口在"隐私同意后"的初始化管线,禁止散落各处自行初始化;
- 发布前用行为检测工具(动态抓包 + 行为沙箱)核对 SDK 实际采集与声明一致(门禁 G3.5)。

### 6.4 数据安全

- 生产数据访问最小权限 + 审计;开发/测试环境**禁止**使用未脱敏的生产数据(测试数据方案见 [14-test-plan.md §8](./14-test-plan.md));
- 数据出境:默认不出境;如用境外云服务/SDK 需专项评估;
- 泄露应急:发现个人信息泄露,按法规时限上报并通知用户,预案纳入 §9 应急演练。

## 7. 内容安全(平台合规生命线)

### 7.1 审核范围与流程

| 内容类型 | 审核方式 | 时机 |
|----------|----------|------|
| 剧集(视频、封面、标题、简介) | 机审(多模态)+ 人审双重,全量 | 上线前(先审后发) |
| 评论、弹幕 | 机审全量实时(文本模型 + 敏感词库),命中进人审队列 | 先审后发或秒级先发后审(按风险等级),高风险词先审后发 |
| 昵称、头像、个性签名 | 机审全量,命中人审 | 修改即触发 |
| 运营活动页/推送文案 | 人审 | 上线前 |

- 审核状态机:`pending → machine_pass/machine_reject → (human queue) → approved/rejected`;**未过审内容对外不可见**(服务端过滤,禁止只靠客户端隐藏);
- 敏感词库/模型策略版本化管理,更新可灰度可回滚;词库版本确认纳入发布门禁 G3.6。

### 7.2 用户侧机制

- 全部 UGC 与剧集提供**举报入口**,举报分级处理 SLA(涉政涉恐类 ≤ 30 分钟响应);
- 违规处置阶梯:删除内容 → 禁言 → 封号,处置留痕可申诉;
- 防刷:评论/弹幕频率限制、新账号发言门槛、垃圾内容聚类识别。

### 7.3 应急响应

- **一键下架能力**:任意剧集/评论可在 5 分钟内全端下架(含 CDN 缓存刷新),每季度演练一次,演练记录纳入发布门禁 G3.6;
- 内容安全值班制度:7×24 响应通道;
- 监管通知处置流程:接收 → 下架 → 回执 → 复盘,全程留痕。

### 7.4 资质与合规(提示项,由产品/法务槽确认)

- 网络视听/网络文化相关资质、剧集备案要求由产品与法务确认后回填本节;技术侧预留"备案号展示、内容分类标签、实名认证"能力位。

## 8. 移动端加固与发布安全

- release 构建:代码混淆(R8/ProGuard、iOS 符号剥离)、禁止可调试(`android:debuggable=false`)、防二次打包校验(签名校验);
- 客户端不存放长期密钥;接口签名密钥使用白盒/native 层保护并接受"可被逆向"的前提 —— **安全决策不依赖客户端密钥**(服务端风控兜底);
- root/越狱环境:支付与登录场景检测并风控加权(不直接拒绝,防误伤);
- 构建产物扫描:硬编码密钥、测试后门、调试开关(纳入门禁 G2.6);
- 依赖供应链:锁定依赖版本(lockfile 必须入库)、私有镜像源、SCA 扫描(门禁 G2.5),防依赖混淆攻击(内部包名保护)。

## 9. 安全工程流程

- **密钥管理**:全部密钥/证书入 KMS 或密管服务,禁止入库;gitleaks 门禁(G1.8)+ 定期全仓历史扫描;泄露即轮换,轮换流程演练;
- **安全评审**:涉及认证、支付、UGC 入口、新增 SDK、新增对外接口的 PR,CODEOWNERS 强制安全 owner 评审;
- **渗透测试**:每次大版本上架前一次内部渗透 + 每年一次外部渗透;发现的 high 以上问题修复前**禁止上架**;
- **漏洞响应 SLA**:critical 24 小时、high 72 小时、medium 14 天;超期进入质量周报红榜;
- **应急演练**:每季度覆盖:token 泄露批量吊销、支付异常熔断(关闭下单保播放)、内容一键下架、数据泄露上报流程。

|----------|-----------------------------------|----------|
