## 1. 字段说明与录入规则

每个任务一行，八列固定：

| 列 | 含义与取值 |
| --- | --- |
| **ID** | `域-序号`。域：`PLN` 计划 / `GOV` 治理闸门 / `CTR` 契约 / `INF` 工程与 CI / `BRG` 桥接层 / `SRV` 服务端基座 / `DAT` 数据层 / `APP` 前端基座 / `I18N` 国际化 / `AUT` 认证 / `CNT` 内容读 / `PBK` 播放令牌 / `PLY` 播放器 / `PRG` 进度与历史 / `WAL` 钱包 UI / `PAY` 支付 / `UNL` 解锁 / `ADS` 广告 / `FEED` 推荐 / `SCH` 搜索 / `EVT` 埋点 / `QA` 质量与测试 / `HRD` 硬化 / `INT` 平台真集成 / `REL` 上架 / `OPS` 运营 / `VER` 独立验证。**ID 一经分配不复用、不改写**，任务顺延时保留原 ID。 |
| **任务** | 一句话可判定的交付物，不写"优化/完善/梳理"这类不可判定动词。 |
| **波** | 目标完成波：`W7`（单波）、`W17–W19`（跨波，以末波为完成期）、`*`（闸门型/连续跟踪，不受波序约束）。 |
| **依赖** | 前置任务 ID 列表，`—` 表示无。**依赖必须已存在于本表**且波序不晚于本任务。 |
| **槽位** | 承担槽，多槽用 `+` 连接，**第一项为主槽**（责任人）。取值：`P1` `P2` `P3`（计划槽）、`A` `B` `C`（工作槽）、`V`（验证槽）、`BIZ`（商务/人工，非代理可执行）。 |
| **验收标准** | 可复现的判定条件，必须含"怎么证明"。禁止"通过测试""质量良好"这类空标准。 |
| **闸门** | 阻塞该任务的闸门（`wave-protocol.md` §6），`—` 表示无。 |
| **状态** | `[ ]` 未开始 / `[~]` 进行中 / `[x]` 完成 / `[!]` 阻塞。 |

**录入规则（对后续计划波强制）**

1. **主槽与波角色必须匹配**：主槽 `P1/P2/P3` → 只能落在计划波 `5k−4`；主槽 `A/B/C` → 只能落在实现波 `5k−3…5k−1`；主槽 `V` → 只能落在验证波 `5k`；主槽 `BIZ` → 不受约束（外部节奏）。
2. **同波依赖仅允许槽位重叠**：若 A 依赖 B 且二者同波，则两者的槽位集合必须有交集（否则跨槽在同一波内串行，等于隐性阻塞）。本表全部同波依赖均满足该条件（§7）。
3. **未列名槽位不等于空闲**：某波未给某工作槽派任务时，该槽按 `wave-protocol.md` §3.2 承担预研、技术债偿还与上周期遗留整改，不新开功能。
4. **新增任务一律进表尾**，由计划波排期，实现波中途不得插队（例外见 `wave-protocol.md` §7）。
