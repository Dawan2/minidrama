## 1. 通用条款（四层共同适用）

1. **铁律不可豁免**：`docs/14-quality-gates.md` §0 的 R1–R6，其中 R1（失败即失败）、R2（禁删测试）、R3（禁跳过失败）、R5（禁空测）**没有豁免通道**。
2. **证据优于声明**：任何"已通过/已验证"必须附可复现证据——命令、输出摘要、报告路径、提交 SHA。无证据的声明视为未完成。
3. **可复现**：他人从干净检出按文档执行即可得到同样结果；文档中没写的隐含步骤即缺陷。
4. **来源可追溯**：涉及官方要求的结论必须标注来源编号（S1–S15）或 PDF 章节（PDF 到手后），禁止无来源的"根据官方文档"。
5. **阻塞如实**：未解除的闸门与阻塞项必须出现在交接文档中，"静默乐观"按不通过处理。

## 6. L-S 可上架 DoD ②：无障碍（a11y）

> **本节为本槽新增的强制条款**。`docs/14-test-plan.md` §6.4 现将 a11y 定为 "P2，不阻断首个上架版本"；本文将其**提升为可上架阻断项**，理由：短剧为**视听内容**且面向多语言市场，字幕与对比度既是无障碍要求也是核心可用性与国际化要求，上线后补的成本远高于随功能建设。
> **该提升与 `docs/14-test-plan.md` §6.4 存在冲突，按 `wave-protocol.md` §3.4 登记为冲突 C-12，裁决人为工作槽 C（质量），会签人计划槽 P1（产品）。裁决前，本节按"目标标准"执行；裁决后由槽 C 回写 `docs/14-*` 并在 backlog 关闭该条目。** 本槽未改写任何 `docs/14-*` 文件。

### 6.1 适用基准

WCAG 2.2 Level AA 中**适用于 TikTok WebView 内竖屏 H5** 的子集。明确 N/A 项：键盘导航与焦点顺序（无物理键盘场景）降级为"不得存在焦点陷阱"；页面级 landmark 结构按移动端简化。

### 6.2 阻断项（不满足即不可上架）

| # | 条款 | 判据 |
| --- | --- | --- |
| S-A1 | **自动化扫描零严重问题** | axe-core（或等价）在 `docs/02-screen-inventory.md` 全部 SCR-01…SCR-13 与 PNL-01…PNL-05 上，**critical + serious 级问题数 = 0**；扫描进 CI 且失败即失败 |
| S-A2 | **文本对比度** | 正文与关键控件 ≥ 4.5:1，大号文本 ≥ 3:1。播放器覆盖层文字必须在**最坏画面帧**下达标（半透明底衬或描边），抽检每部剧 3 帧 |
| S-A3 | **触达区域** | 所有可交互元素有效触达区 ≥ 44×44 CSS px（播放器手势区除外，但其功能必须有 ≥44px 的可见控件等价入口） |
| S-A4 | **图标按钮有名称** | 纯图标控件（点赞、收藏、选集、倍速、关闭、返回）具备 `aria-label` 或等价可访问名称，且随 i18n 一起翻译（英文必备） |
| S-A5 | **字幕** | 全部剧集提供字幕轨（至少与内容语言一致的一条），播放器提供字幕开关；字幕缺失的剧**不得进入内容池**（并入 `01-product-scope` §4.6 内容准入检查项） |
| S-A6 | **不以单一感官通道传达信息** | 解锁状态、错误、加载不得**仅靠颜色或仅靠动效**传达，必须同时有文本或图标 |
| S-A7 | **动效可控** | 尊重 `prefers-reduced-motion`：开启时禁用非必要转场与自动轮播；无每秒 3 次以上闪烁内容（光敏性安全） |
| S-A8 | **无焦点陷阱** | 面板/弹层（PNL-01…PNL-05）可通过可见控件关闭，不依赖系统返回；屏幕阅读器焦点不被困在已关闭层 |
| S-A9 | **屏幕阅读器人工抽查** | VoiceOver（iOS）+ TalkBack（Android）走查核心旅程 U1–U3：可听到有意义的控件名称与状态变化（如"第 12 集，已解锁"），无"按钮 按钮 按钮"式裸读 |
| S-A10 | **文字缩放** | 系统字号放大到 200% 时核心信息不截断、不重叠（允许布局重排） |

### 6.3 观测项（记录但不阻断首发）

完整 landmark/heading 层级、复杂手势的替代操作全集、音频描述（AD）轨——登记进 backlog，目标周期由计划波排定。

## 7. L-S 可上架 DoD ③：CI 零跳过（no skipped CI）

> 本节把铁律 R1–R5 从"约定"变成"可被机器检出的判据"。**所有条款由 CI 自审 job 强制**（backlog `INF-004`），人工评审为第二道防线。

### 7.1 流水线完整性

| # | 条款 | 检出方式 |
| --- | --- | --- |
| S-C1 | 无 `continue-on-error: true`、无 `allow_failure`、无 `soft fail`、无 `\|\| true` 吞掉退出码 | 自审 job 扫描 workflow 文件与脚本，命中即失败 |
| S-C2 | 无被禁用的 job/workflow：`if: false`、被注释掉的门禁步骤、`workflow_dispatch` 单独触发用于绕过 | 自审 job diff 对比上一 release 的 job 清单，**job 数量减少必须有豁免记录** |
| S-C3 | 无 echo-only / 恒成功占位步骤 | 每个门禁步骤必须调用真实校验命令；新增步骤在评审 checklist 中核对 |

| S-C6 | 门禁反向验证有效 | 每条 L1/L2/L3 门禁至少有一次"注入违规 → 变红"的实证记录，且记录不早于上一次门禁配置变更 |

### 7.2 测试跳过

| # | 条款 | 检出方式 |
| --- | --- | --- |
| S-C7 | 无未标注的跳过 | 扫描 `.skip(`、`.only(`、`xit(`、`xdescribe(`、`@Disabled`、`@Ignore`、`pytest.mark.skip`；每处必须形如 `// SKIP(#1234, expires=2026-09-30): 原因` |
